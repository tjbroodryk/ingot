{{ .Chart.Name }} {{ .Chart.AppVersion }} — release {{ .Release.Name }} in {{ .Release.Namespace }}.

The schema is already current: the migration ran as a pre-install hook, out of
the same image the server runs, so there was never a moment where one was ahead
of the other.

  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "ingot.fullname" . }}-server

{{- if .Values.ingress.enabled }}

Reachable at https://{{ .Values.ingress.host }} — the site at /, the API under
/api. One host, so the dashboard calls its own origin and CORS never enters
into it.

  curl https://{{ .Values.ingress.host }}/api/health
{{- else }}

No Ingress. To look at it without one:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "ingot.fullname" . }}-server 3002:{{ .Values.server.service.port }}
  curl http://localhost:3002/api/health
{{- if .Values.app.enabled }}

The dashboard needs only its own port — its nginx forwards /api to
{{ include "ingot.app.apiUrl" . }}:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "ingot.fullname" . }}-app 8080:{{ .Values.app.service.port }}
  open http://localhost:8080/dashboard/
{{- end }}
{{- end }}

There is nothing to sign up to. The one account, `{{ .Values.config.auth.account }}`, was
created at boot, and its key is `INGOT_API_KEY` in the Secret
`{{ include "ingot.secretName" . }}`:

  KEY=$(kubectl -n {{ .Release.Namespace }} get secret {{ include "ingot.secretName" . }} \
    -o jsonpath='{.data.INGOT_API_KEY}' | base64 -d)
  curl -X POST http{{ if .Values.ingress.enabled }}s://{{ .Values.ingress.host }}{{ else }}://localhost:3002{{ end }}/api/v1/{{ .Values.config.auth.account }}/cast \
    -H "authorization: Bearer $KEY" \
    -H 'content-type: application/json' -d '{"name":"first ingot"}'
